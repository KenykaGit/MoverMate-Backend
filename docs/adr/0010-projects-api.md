# ADR 0010. API проектов: доступ, модель чтения, напоминания о переезде

**Статус:** принято (2026-10-17)

## Контекст

Модуль `projects` — первый бизнес-модуль, открытый через API: проекты, участники и
напоминания о дате переезда. Фронтенд описал желаемый контракт в
[api-endpoints.md](../../api-endpoints.md), раздел 4. Требования кейса:

- проект видят только его участники, удаляет только владелец;
- несколько участников меняют один проект одновременно;
- напоминание о переезде полезно в осмысленное местное время, а у даты переезда времени нет;
- ни одно уведомление не теряется ([ADR 0009](0009-moving-domain-aggregates.md), outbox);
- мобильный клиент повторяет запросы после обрыва связи.

## Решение

- **Чужим — 404, участнику без прав — 403.** Нет проекта, он удалён или пользователь не
  участник — один ответ 404 `project_not_found`: посторонний не узнаёт, что проект существует.
  403 `not_project_owner` получает только участник, который пытается выполнить действие
  владельца (удаление проекта). Участие проверяет use case через
  `get_member_project_or_raise` ([lookup.py](../../src/app/application/projects/lookup.py)).
- **Отдельная модель чтения (CQRS-lite).** Ответу нужны данные, которых нет в агрегате:
  username владельца, `created_at`/`updated_at`, которые ставит БД. Порт
  `AbstractProjectReader` возвращает DTO прямыми запросами по колонкам. Изменяющий use case
  меняет агрегат через репозиторий и после коммита читает ответ через reader.
- **Изменения проекта сериализуются.** Каждый изменяющий use case загружает проект с
  `SELECT … FOR UPDATE` (`get_by_id(for_update=True)`). Параллельные правки участников и
  напоминаний выполняются по очереди, а не теряют друг друга и не упираются в конфликт PK
  дочерних строк.
- **Напоминание о переезде — 09:00 по часовому поясу проекта.** У проекта есть
  `time_zone` (IANA, Value Object `TimeZone` сверяет имя с базой tz). Момент отправки —
  `Project.moving_reminder_at(offset)`: день `moving_date − offset` в
  `MOVING_REMINDER_LOCAL_TIME` (09:00) по местному времени, переведённый в UTC. Смещение 0 —
  утро дня переезда: диапазон расширен с 1..365 до 0..365 в домене и в CHECK (миграция 0006).
- **Напоминания ставятся в outbox в той же транзакции.** Смена `moving_date` или
  `time_zone` отменяет ожидающие напоминания и создаёт новые. Отмена — один атомарный
  `UPDATE … WHERE status = 'PENDING'` (`cancel_pending*`), то же правило, что
  `Notification.cancel()`; его страхует триггер статуса в БД. Отмена выполняется до вставок,
  поэтому частичный UNIQUE ожидающих напоминаний не нарушается.
- **Удалить аккаунт, владеющий активными проектами, нельзя:** 409 `user_owns_projects`
  (решение 17 в [db-design.md](../db-design.md)). Участие удалённого пользователя в чужих
  проектах сохраняется, но скрыто из списка участников, поэтому `RestoreUser` возвращает его.
- **Действующий контракт важнее списка пожеланий фронтенда.** Сохранены конверт
  `{"error": {...}}` и коды в нижнем регистре ([ADR 0004](0004-error-contract-and-versioning.md)):
  `project_not_found` вместо `NOT_FOUND` и т. п.; у каждого вида «не найдено» свой код вместо
  одного общего. Refresh-токен по-прежнему передаётся в теле, cookie в этой задаче не вводится.
- **Явные `operationId`** есть пока только у маршрутов проектов; у `auth` и `users` они
  сгенерированы FastAPI.

## Альтернативы

- **403 для не-участника.** Понятнее клиенту, но раскрывает существование проекта по id.
- **Таймстемпы и username в доменной сущности.** Одна модель для записи и чтения, но домен
  стал бы хранить служебные поля БД и данные чужого агрегата (`User`), а каждое изменение
  проекта читало бы пользователей.
- **Оптимистическая блокировка (колонка версии).** Не держит строку, но параллельные правки
  участников превращаются в 409 и повторы на клиенте. Правки одного проекта редки и коротки,
  блокировка строки дешевле.
- **Фиксированное время в UTC.** Не нужен часовой пояс, но 09:00 UTC — это 12:00 в Москве и
  18:00 во Владивостоке.
- **Перенос `scheduled_at` ожидающих напоминаний на месте.** Меньше строк, но отдельная
  логика для уже прошедших моментов и для новых участников; «отменить и создать заново»
  переиспользует путь создания.

## Последствия

- Каждый изменяющий use case проекта начинается с блокировки строки `projects`; чтение
  (`GET`) блокировку не берёт.
- Ответ изменяющего эндпоинта отражает закоммиченное состояние, включая `updated_at` из БД.
- Часовой пояс нужен только напоминаниям о переезде. Сроки задач остаются абсолютными
  (`timestamptz`).
- `downgrade()` миграции 0006 удаляет напоминания со смещением 0 и отменяет их ожидающие
  уведомления: старый CHECK их не допускает.
- Уведомления пока только ставятся в очередь: воркера отправки нет (см. «Известные
  ограничения» в [architecture.md](../architecture.md#известные-ограничения)).
- Задача на будущее: явные `operationId` для `auth` и `users`.
