# ADR 0006. Nginx как единственная точка входа; rate limit по IP клиента

**Статус:** принято

## Контекст

Rate limit по IP бессмысленен, если клиент может подставить любой `X-Forwarded-For`.
Клиенту нужен ответ в формате API, даже когда api перезапускается. Запрос должен
прослеживаться от края до базы одним идентификатором.

## Решение

- nginx 1.30 (stable-ветка) слушает `:8000` локально и `:80` в prod. Контейнер `api` порты не публикует,
  поэтому uvicorn с `--proxy-headers --forwarded-allow-ips="*"` безопасно доверяет
  заголовкам: прийти они могут только от nginx.
- nginx **перезаписывает** `X-Forwarded-For` значением `$remote_addr`, а не дописывает к
  нему. За TLS-балансировщиком включается `set_real_ip_from <cidr>` только для его адресов.
- `X-Request-ID`: значение клиента сохраняется, если передано, иначе генерируется
  `$request_id`. api принимает только безопасные значения (`[A-Za-z0-9._-]{1,64}`) и эхом
  возвращает id в ответе.
- JSON access-лог nginx содержит `request_id`, `status`, `upstream_status`,
  `upstream_response_time`.
- 502/503/504 от самого nginx отдаются как `{"error": {"code": "service_unavailable", ...}}`
  с `Retry-After: 5`. `proxy_next_upstream off`: неидемпотентный POST не повторяется.
- Upstream резолвится на каждый запрос через `resolver 127.0.0.11` и переменную: после
  пересоздания контейнера api nginx не держит старый IP.
- `/metrics` снаружи закрыт (404), Prometheus читает его внутри сети.
- **Rate limit** реализован в приложении (Redis, fixed window 60 с): scope `api` (120/мин) на
  все `/api/v1/*` и строгий `auth` (10/мин) поверх него на register/login/refresh. Заголовки
  `X-RateLimit-*` добавляются к любому ответу, включая ошибки, а 429 содержит `Retry-After`.

## Альтернативы

- **`limit_req` в nginx.** Не требует Redis, но счётчики живут в памяти каждого инстанса
  nginx, лимит нельзя менять по пользователю или эндпоинту из кода, и нет единого формата
  ответа с заголовками остатка.
- **Traefik/Envoy.** Мощнее, но для одного сервиса это лишняя сложность.

## Последствия

- Лимиты общие для всех инстансов api, потому что живут в Redis, и при его отказе не
  действуют ([ADR 0003](0003-postgres-and-redis-fail-open.md)).
- Fixed window пропускает до 2× лимита на стыке окон: для защиты от злоупотреблений это
  приемлемо.
