# ADR 0001. Clean Architecture и DDD: слои и направление зависимостей

**Статус:** принято

## Контекст

Шаблон должен оставаться понятным, когда доменных модулей становится десять, и позволять
проверять бизнес-логику за секунды, без Docker. В типичном FastAPI-проекте правила
размазаны по роутам, pydantic-схемам и ORM-моделям, поэтому каждый тест требует базу.

## Решение

- Пять слоёв: `domain` → `application` → `infrastructure` → `presentation` и точка сборки
  (`ioc`, `config`, `main`). Зависимости направлены только внутрь.
- **Domain** — чистый Python. Value Objects (`Email`, `Username`, `RawPassword`,
  `PasswordHash`) нормализуют и валидируют себя сами. Сущности —
  `dataclass(slots=True, kw_only=True, eq=False)` с равенством по id (базовый класс `Entity`).
  Время передаётся в методы явно (`now=`), поэтому домен детерминирован.
- **Application** — use case как класс с `async def __call__(dto) -> DTO`. Use case
  управляет транзакцией (`uow.commit()`). Общие сервисы (`TokenPairIssuer`) не коммитят.
  Внешний мир доступен только через порты (`application/interfaces/`, ABC). Логирование
  идёт через stdlib `logging`, без structlog.
- **ORM отдельно от домена.** Модели SQLAlchemy живут в `infrastructure/db/models/`, а
  перевод между ORM и доменом выполняют статические мапперы `to_domain`/`to_model`.
- **Pydantic только в presentation** и описывает лишь форму JSON. Бизнес-правила проверяет
  домен, нарушения возвращаются как 422 с конкретным `code`.
- Границы проверяются автоматически: [.importlinter](../../.importlinter) (5 контрактов) и
  AST-тест [test_architecture.py](../../tests/unit/test_architecture.py).

## Альтернативы

- **Модульный монолит со слоями внутри модуля** (`modules/<feature>/{domain,service,router}.py`).
  Меньше файлов и проще навигация по фиче, но слои размываются: модуль сам решает, что ему
  можно. Здесь важнее единые для всех фич правила, которые проверяет машина.
- **Pydantic-модели как домен.** Меньше кода, но домен начинает зависеть от библиотеки
  валидации, а валидация смешивается с бизнес-правилами.
- **Active Record (ORM-модель = сущность).** Быстро на старте, но unit-тест домена требует
  SQLAlchemy, а ленивые загрузки в async-коде становятся минным полем.

## Последствия

- Больше файлов: DTO, мапперы и порты повторяют структуру сущностей. Это цена изоляции.
- Около 340 unit-тестов (домен, use cases на фейках, контракты, проводка DI) выполняются за
  пару секунд, без Docker.
- Новый модуль добавляется по чек-листу в [architecture.md](../architecture.md#как-добавить-модуль),
  и архитектурный тест не даст пропустить шаг.
