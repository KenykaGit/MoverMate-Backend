# ADR 0013. Чтение инвентаря через read model, страницы по курсору

**Статус:** принято (2026-10-17)

## Контекст

Экраны фронтенда ([api-endpoints.md](../../api-endpoints.md), разделы 6–7) показывают коробку
вместе с комнатой назначения, создателем, числом вещей и превью содержимого, а вещь — вместе
с комнатой «откуда» и коробкой. В проекте сотни коробок и тысячи вещей, а мобильный клиент
листает их страницами. Если собирать такое представление из агрегатов через репозитории,
получится по запросу на каждый объект (N+1), а сортировка и поиск (FTS, ранжирование) всё
равно живут в SQL.

## Решение

- **Запись — через агрегаты, чтение — через read model.** Use case загружает агрегат
  репозиторием, проверяет правила методами сущности и сохраняет изменения. Ответ он берёт из
  `AbstractInventoryReadModel`, которая сразу возвращает DTO: коробку — двумя запросами на
  страницу (строки и одно окно `row_number()` для превью и количества), вещь — одним
  запросом с join. Read model ничего не меняет и права не проверяет: это делает use case.
- **Порт лежит в фиче** (`application/inventory/read_model.py`), потому что возвращает DTO
  фичи, а `application/interfaces` не может импортировать фичи. Архитектурный тест знает этот
  модуль как «не use case».
- **Страницы по курсору (keyset).** Курсор — непрозрачный base64url-JSON с ключом последней
  строки: `number` у коробок, `(priority, lower(name), id)` у вещей. Запрос `WHERE ключ >
  курсор ORDER BY ключ LIMIT n + 1` использует индексы и не деградирует на дальних страницах,
  а `+1` строка говорит, есть ли продолжение, без `COUNT(*)`. Поиск сортирует по рангу FTS,
  поэтому пагинируется по offset.
- **Статус коробки пишется только сравнением-с-обменом.** `update()` репозитория коробок
  статус не трогает; `change_status()` выполняет `UPDATE … WHERE status = :expected` и
  превращает ноль строк в `box_status_conflict` (409). Параллельная смена статуса не
  перетирается молча, а триггер БД сверяет переход с матрицей домена.

## Альтернативы

- **Ленивые связи ORM и сборка DTO из агрегатов.** Меньше SQL, но N+1 и `MissingGreenlet`
  в async, а агрегаты потянули бы связи с чужими модулями (ADR 0010 их запрещает).
- **Offset-пагинация везде.** Проще, но дальние страницы медленнее, а вставка во время
  листания сдвигает страницы. `total` фронтенду не нужен: счётчики даёт сводка проекта.
- **Оптимистическая блокировка через колонку `version`.** Универсальнее, но требует колонки
  и миграции ради одного поля, для которого хватает сравнения с ожидаемым статусом.

## Последствия

- SQL read model проверяется интеграционными тестами на PostgreSQL
  (`tests/integration/api/test_inventory_scenarios.py`). Фейк read model в unit-тестах
  собирает представления из фейковых репозиториев и не повторяет фильтры и пагинацию.
- Ограничения курсора по ключу перечислены в «Известных ограничениях» `architecture.md`.
